PR #391 recovery follow-up: ARRR commits an acknowledged funding transaction ID
before looking up its output. An unknown output index is represented as -1;
restart recovery retries the saved transaction without funding again or binding
another deposit. Sellers skip old spent offer candidates instead of closing an
open offer, and unresolved legacy confirmed-marker records retain their audit
cooldown so later recoverable records can progress.

ARRR contract discovery: reads both Pirate address-index categories when a
server misclassifies P2SH funding or spends. Matches contract scripts, verifies
raw output values/indexes, merges duplicate and mixed index entries, and fails
on incomplete/conflicting evidence. This fixes the confirmed Musiqo funding
being reported as HTLC_UNFUNDED. Update buyer and seller Core; existing JNI
0.3.11 and matching frontend builds remain compatible. No new native publication
or migration is required. Live refund and complete trade acceptance remain to
be tested. See arrr-address-index-compatibility.md.

New wallet-history correction: the previous test JAR retained an unsafe verbose
Electrum decimal conversion, separate from the earlier raw/witness reader fix.
BTC, LTC, DOGE, DGB and RVN now share exact numeric conversion, with verified
wire-output recovery when the JSON value lacks atomic precision. Ordinary exact
replies need no extra request. Recovery checks transaction ID, output count,
scripts and complete transaction bytes. It does not round monetary values.
ARRR history rejects fractional/overflowing atomic amounts; both QORT API amount
conversions reject overflow. XMR retains its exact 12-decimal amount handling.
